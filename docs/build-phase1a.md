## 工程0：受け入れの検査と下ごしらえ

電池をつなぐ前に、技適と極性を確かめる。ここで見落とすと後で取り返しがつかない。

**検査**

- [ ] XIAO の本体（シールドかラベル）かパッケージに技適マークがあるか確かめる。**マークがなければ Wi-Fi／BLE を使わない**（CLAUDE.md の不変の制約。Amazon の出品ページには技適の記載がなかった）
- [ ] N20 のラベルを見て、走行用（300rpm）と高減速（15rpm）を分けて袋に書いておく。見分けがつかなければ 1S で軽く回して、遅いほうが高減速
- [ ] リポ電池の電圧をテスターで測る（3.7〜4.2V 程度なら正常。3.0V を切っていたら使わない）
- [ ] **電池のコネクタの赤が＋か**をテスターで確かめる。ピグテールを電池に挿した状態でも、赤線が＋になっているか確かめる（JST-PH の赤黒はメーカーで逆のことがある）
- [ ] 購入表と数を突き合わせる

**はんだ付け**

- [ ] DRV8833 基板にピンヘッダーを付ける。8本の列（GND・nFAULT・BIN1・BIN2・VCC・nSLEEP・AIN2・AIN1）はピンを下向きにしてブレッドボードの f 列 19〜26 番に横一列で挿す（GND が 26番、AIN1 が 19番。ブレッドボードは右端が 1番の向き）。4本の列（BOUT1・BOUT2・AOUT2・AOUT1）はピンを上向きにして、モーターの線を上からかぶせる（2列の間隔がブレッドボードの穴の間隔に合う保証がないため）。図は「DRV8833 ピンヘッダーの付け方」の Artifact
- [ ] N20 3個（走行2、高減速1）の端子にリード線を付け（リード線はオス-オスのジャンパーを半分に切って使う。ピンの側がブレッドボードに挿さる）、端子間に 0.1µF を付ける。熱収縮チューブで絶縁する
- [ ] マイクロスイッチにリード線を2本付ける（COM と NO。端子がラグ形でブレッドボードに挿せないため）
- [ ] XIAO の裏面パッド BAT+／BAT− に、ピグテールのうち**電池のコネクタに嵌まる側**（セットの「オス」）を付ける。**赤を BAT+**（電池に挿して、ピグテールの赤が＋になることをテスターで確かめてから）。スイッチは工程5 で間に入れる（それまでは電池を抜き差しして電源を切る）

**確認**：テスターで BAT+ と BAT− の間が短絡していないこと。電池を挿して BAT+ が＋、BAT− が−になること。

## 工程1：XIAO 単体（カメラ映像をブラウザに出す）

電池はつながず、USB-C 給電だけで動かす。

- [ ] PlatformIO を入れて、`cd firmware && pio run` でビルドが通ることを確かめる（決めてほしいこと 6）
- [ ] カメラのサンプル（Arduino の CameraWebServer など）を書き込み、XIAO の IP にブラウザでつないで映像が出ることを確かめる。カメラのリボンケーブルが拡張ボードに挿さっているかも確かめる
- [ ] `firmware/src/secrets.h.example` を `secrets.h` にコピーし、Wi-Fi（2.4GHz）とサーバ（PC の IP、トークン）を書き込む
- [ ] microSD は挿さない（D8〜D10 と信号線を共用。録画もしない方針）

**確認**：映像がブラウザに出る。シリアルモニタ（`pio device monitor`）に起動ログが出る。

## 工程2：中継サーバとブラウザ（キー入力 → XIAO の LED）

- [ ] `cd server && npm test` と `cd firmware && make test` が通ることを確かめる
- [ ] `cd server && MRC_TOKEN=<8〜16文字> npm start` で中継サーバを起動する
- [ ] 本番のファームウェアを書き込む：`cd firmware && pio run -t upload`
- [ ] WS2812B モジュールを配線する：DIN←330Ω←D10、GND→GND、**VDD→VBAT**（電池から。3.3V では電源の下限 3.5V を下回る）。モジュールが届くまではこの行を飛ばす
- [ ] 電池をつなぎ、`http://127.0.0.1:8080/` を開く。機体の状態が表示され、LED の色が変わることを確かめる

**確認**：ブラウザに往復遅延と電池電圧が出る。キーを押すとブラウザの表示が反応する（LED があれば LED も）。LED がなくても、ブラウザの表示とシリアルモニタのログで確認できれば工程3へ進んでよい。

## 工程3：DRV8833 と走行モーター（ブレッドボード）

- [ ] DRV8833 の VM を VBAT に、GND を GND につなぐ。**モーターの電源は 3V3 から取らない**
- [ ] VM のすぐそばに 100µF（極性に注意）と 0.1µF を並列に入れる
- [ ] **nSLEEP を 3.3V につなぐ**。これがないとモーターが回らない（内部でプルダウンされている。W2 には描かれていない）。Kitronik の資料は「High にするときは 20k〜75kΩ を通す」としている（nSLEEP に 6.5V を超える電圧がかかるのを防ぐため）。3.3V から取るなら直結でも超えないが、手元に 22kΩ 前後の抵抗があれば挟む
- [ ] AIN1/AIN2←D1/D2（左）、BIN1/BIN2←D3/D4（右）。AOUT1/2 に左モーター、BOUT1/2 に右モーター
- [ ] 車輪を浮かせた状態で W/A/S/D を押し、前進・後退・左右旋回を確かめる。逆に回るモーターは AOUT（BOUT）の2本を入れ替える

**確認**：W で両輪が前に、S で後ろに、A／D で左右が逆に回る。キーを離すと止まる。

## 工程4：停止機能と電池電圧の監視

- [ ] D0 に分圧をつなぐ：VBAT─100kΩ─D0─100kΩ─GND。下側の 100kΩ に 0.1µF を並列に入れる
- [ ] ブラウザの電池電圧とテスターの VBAT が近いことを確かめる（ずれが大きければメモしておき、ファームで補正する）
- [ ] 車輪を浮かせて W を押したまま、次の3つを試す。どれも 300ms 以内に止まること
  - Wi-Fi ルーターの電源を抜く
  - ブラウザのタブを開発者ツールで一時停止する
  - 中継サーバを止める（Ctrl+C）
- [ ] 低電圧の動作：3.5V で LED が橙（警告）、3.3V で走行とジャンプが止まり LED が赤の点滅。電池を使い切るまで待たずに、可変の電源があればそれで、なければ工程7 の連続動作のときに確かめる

**確認**：3通りとも止まる。電池電圧の表示がテスターとおおむね合う。

## 工程5：車台に組み付けて机の上を走らせる

- [ ] 走行モーター2個を板（約120×60mm）の後ろ寄りの左右の端に、結束バンドで固定する（ブラケットの代わり）
  - ギア箱の両脇に、キリで結束バンドを通す穴を2つ開ける（ギア箱の幅 約12mm の外側）
  - ギア箱の下にクッション入り両面テープを貼り、結束バンドでギア箱を板に締める。モーターの金色の部分は締めない
  - 左右の軸が一直線になり、板の縁と直角になるように合わせる。ホイールが板に当たらないよう、軸は板の外へ出す
- [ ] ホイールを軸の D カットに合わせて押し込む
- [ ] 前側にボールキャスターを付け、車体が水平になる高さに合わせる（32mm ホイールの車軸の高さは約16mm）
- [ ] ブレッドボード、電池、XIAO を両面テープか結束バンドで載せる。カメラは前に向ける
- [ ] 電池の＋と XIAO の BAT+ の間にスライドスイッチを入れる（定格 0.5A。机上はこのまま。決めてほしいこと 5）
- [ ] 机の上を走らせる。落ちないよう、最初は床か机の周りに囲いを作る

**確認**：スイッチで電源が入る・切れる。映像を見ながら机の上を走れる。

## 工程6：ジャンプ用モーター、カム、スイッチ

- [ ] MOSFET IRLU3410 を配線する：ゲート←100Ω←D5、ゲート─100kΩ─GND、ソース→GND、ドレイン→高減速モーター→VBAT（ピンのピッチが 2.29mm なので、少し広げて挿す）
- [ ] 1N5819 をモーターに並列に入れる。**帯の側を VBAT 側**
- [ ] 高減速モーターを走行モーターと同じやり方（結束バンドと両面テープ）で板に固定し、軸に仮のカムを付ける。1回転に1回マイクロスイッチのレバーを押す位置にスイッチを置く
- [ ] マイクロスイッチの COM を GND、NO を D9 につなぐ
- [ ] Space を押すとカムが1回転し、スイッチで「チャージ完了」を検知して止まることを確かめる。同じジャンプ ID では2回動かないこと
- [ ] MOSFET の発熱を指で確かめる（3.3V 駆動時のオン抵抗は未確認。熱ければデータシートで確かめる）

**確認**：Space 1回につきカムが1回転して止まる。車体が実際に跳ぶ必要はない（機構の本番は 1-b2）。

| 体感ラグ | 画面にストップウォッチを出してキーを押し、スマホのスロー撮影で「押した瞬間」から「映像が動いた瞬間」までのコマ数を数える | 記録するだけ（150〜250ms 程度の見込み） |
| 往復遅延 | 中継サーバのログ | 数十ms |
| 停止機能 | 工程4 の3通りを、車台に載せた状態でもう一度 | 300ms 以内 |
| 電源の安定 | 全モーターを同時に動かし（走行＋ジャンプ）、テスターで VBAT を測る。車輪を手で押さえて止める試験もする | XIAO が再起動しない（再起動したら予備の 100µF を BAT+ の近くに足す） |
| マイクの雑音 | 停止中と走行中にそれぞれ聞き比べる（録音はしない方針なので、ブラウザで聞いて種類をメモする） | 雑音の種類を記録し、対策を決める |
| 連続動作 | 満充電から走行と映像を続け、電池電圧を記録する | 30分以上 |

満充電は XIAO の USB-C で約11時間かかる（充電電流 100mA）。連続動作の試験は前の晩から充電しておく。

## 気をつけること（まとめ）

- 電池の極性は、つなぐたびにテスターで確かめる
- モーターの電源は VBAT から直接取る。3V3 からは取らない
- DRV8833 の nSLEEP を 3.3V に、WS2812B の VDD を VBAT につなぐ
- 1N5819 の帯は VBAT 側、100µF の電解コンデンサは極性に注意
- microSD は挿さない。映像と音声は録画・録音しない
- D6／D7／D8 は 1-b 用の予約なので、1-a では何もつながない
- リポは耐火のバッグに入れて充電・保管する

## 図面との食い違い（要確認）

組み立ての前に、次の2点を決めて W2（`docs/drawings/src/d1.py`）を直す。

1. **WS2812B の VDD**：W2 では 3V3 につないでいるが、モジュールの電源は 3.5〜5.3V（[plan-phase1a.md](plan-phase1a.md) の配線の注意）。この手順書では VBAT につなぐ
2. **DRV8833 の nSLEEP**：W2 に描かれていない。Kitronik 5108 では 3.3V につなぐ必要がある
